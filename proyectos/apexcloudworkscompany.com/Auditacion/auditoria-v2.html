03 Seguridad
VulnerabilidadRiesgoDetalle
🔴 Admin token hardcodeado en cliente CRÍTICO admin.js línea 13: const _t = ['apex','Admin','2026','!'].join('') — cualquiera puede obtenerlo con DevTools y hacer llamadas administrativas directas al Apps Script (crear clientes, editar finanzas, borrar proyectos).
🔴 URL del Apps Script expuesta CRÍTICO La URL del endpoint Apps Script está en admin.js y portal.js (código público). Combinada con el admin token hardcodeado, cualquier script externo puede hacer CRUD completo sobre los datos.
🔴 Autenticación basada en localStorage CRÍTICO El gate del admin guarda el hash SHA-256 de la contraseña en localStorage. localStorage es accesible por cualquier JS de la página → XSS = acceso admin total. Sin expiración ni revocación.
🟠 innerHTML sin escape en builders SVG ALTO buildRevenueRing(), buildLeadFunnel() y buildActivityFeed() usan template literals con datos de LIVE sin pasar por la función h(). Si un nombre de cliente o proyecto contiene <script>, se ejecuta.
🟠 Password hashes en Google Sheets ALTO portal-apps-script.gs guarda password_hash directamente en la hoja "Usuarios". Si el Spreadsheet se comparte accidentalmente, los hashes de todos los clientes quedan expuestos. Sin salt por usuario.
🟠 Sin CSRF tokens en POST al Apps Script ALTO apiPost() envía JSON sin token CSRF. Una página maliciosa en otro dominio podría enviar requests a la misma URL con el admin token (si lo obtiene) y modificar datos.
🟡 Sin rate limiting en login del portal MEDIO El endpoint login del Apps Script no limita intentos fallidos. Permite fuerza bruta ilimitada contra credenciales de clientes.
🟡 Tres estrategias de auth inconsistentes MEDIO admin.html usa localStorage+SHA-256, portal.js usa sessionStorage+SHA-256, auth.js tiene código Cognito sin usar. Superficie de ataque triple y mantenimiento inconsistente.
🟢 Security headers del admin BIEN admin.html tiene <meta name="robots" content="noindex, nofollow">. La función h() de escape existe y se usa en la mayoría de renders.
⚠ Acción inmediata requerida: El token admin hardcodeado + URL del Apps Script pública permiten a cualquier persona con acceso al código JS ejecutar operaciones admin completas. Prioridad máxima antes de escalar el panel.

❌ Actual — admin.js línea 13

async function apiPost(body) {
  return fetch(PORTAL_AS_URL, {
    method: 'POST',
    body: JSON.stringify({
      adminToken: _t,
      ...body
    })
  }).then(r => r.json());
}
✅ Propuesto — sin token en cliente
// Token se maneja en servidor (lambda/proxy)
// No hay token en el cliente

async function apiPost(accion, body) {
  const token = sessionStorage.getItem('apex_session');
  return fetch('/api/admin', {  // proxy propio
    method: 'POST',
    headers: {
      'Authorization': `Bearer ${token}`,
      'Content-Type': 'application/json'
    },
    body: JSON.stringify({ accion, ...body })
  }).then(r => r.json());
}
